# Project documentation and promotion

## Purpose
Explain the project and present it on GitHub without changing the reference.
## Ownership
README support material and promo/ assets.
## Local contracts
- Promotional art is decorative, never technical evidence or a replacement for the hardware map.
- Real interface screenshots must come from the working Atlas and retain its content.
- README images link to the actual app; ordinary GitHub files remain directly accessible.
- Preserve source attribution and uncertainty. An explanatory report is not evidence acceptance.
## Work guidance
Record generated asset prompts and provider in promo/README.md. Use descriptive alt text and local repository asset paths.
## Verification
Check image paths, rendered README and launch/download/source links. No application behavior changes belong in a presentation-only update.
